1. Обнаруженная проблема

Во время тестирования J.A.R.V.I.S. выявлены проблемы с произношением математических выражений и длинных форматированных ответов.

Текущая система:

- Rust + Tauri 2 + Next.js.
- Groq, модель "openai/gpt-oss-120b".
- Собственный Rust TTS на Xeon.
- Оригинальный голос J.A.R.V.I.S.
- Потоковая генерация и воспроизведение PCM.

Эксперимент показал, что длинный ответ, состоящий из обычного русского текста, воспроизводится плавно.

Однако математические выражения, степени, специальные символы и Markdown-разметка иногда произносятся неправильно или вызывают проблемы при озвучивании.

Главная цель — сделать речь J.A.R.V.I.S. естественной даже при сложных математических и технических ответах.

2. Создать Speech Text Normalizer

Реализуй отдельный модуль нормализации текста на Rust.

Например:

"src-tauri/src/speech_normalizer.rs"

Он должен преобразовывать текст LLM в форму, подходящую для русского синтеза речи.

При этом необходимо строго разделить:

- "display_text" — оригинальный ответ для интерфейса.
- "speech_text" — нормализованный текст для Rust TTS.

Оригинальный текст с формулами должен сохраняться в истории диалогов и отображаться в HUD.

Не изменяй смысл ответа и не подменяй математические значения.

3. Правильное произношение математики

Реализуй преобразование распространённых математических выражений.

Примеры:

Исходный текст| Озвучивание
"3²"| три в квадрате
"3^2"| три во второй степени
"3³ = 27"| три в кубе равно двадцати семи
"2^10 = 1024"| два в десятой степени равно тысяче двадцати четырём
"√16 = 4"| квадратный корень из шестнадцати равен четырём
"5 × 8 = 40"| пять умножить на восемь равно сорока
"12 ÷ 3 = 4"| двенадцать разделить на три равно четырём
"2/3"| две третьих, если выражение является дробью
"25%"| двадцать пять процентов
"π"| пи
"∞"| бесконечность
"3 > 2"| три больше двух

Обрабатывай математические выражения с учётом контекста.

Не используй простую глобальную замену символов, которая может испортить даты, адреса API, версии программ или технические идентификаторы.

Для неоднозначных выражений реализуй безопасное поведение.

4. Обработка Markdown и HTML

Перед отправкой текста в TTS корректно обрабатывай:

- Заголовки Markdown.
- Жирный и курсивный текст.
- Маркированные и нумерованные списки.
- Таблицы.
- Разделители.
- Ссылки.
- HTML-теги.
- Кодовые блоки.
- Математическую запись LaTeX.

J.A.R.V.I.S. не должен произносить служебные символы разметки.

Вместо чтения таблицы как набора символов преобразуй её в понятную последовательность предложений, сохраняя важную информацию.

Для кода, команд и ссылок предусмотрите отдельный режим чтения, не искажающий технические данные.

5. Интеграция с потоковым Rust TTS

Подключи нормализатор к существующему голосовому конвейеру.

Архитектура:

Groq → Streaming LLM → Text Buffer → Speech Normalizer → Rust TTS → PCM → Динамики.

Требования:

1. Сохрани настоящее потоковое воспроизведение.
2. Не ожидай полного ответа LLM, чтобы начать озвучивание.
3. Учитывай, что математическое выражение может поступать частями из SSE.
4. Не отправляй незавершённые формулы на озвучивание.
5. Разделяй речь на естественные фразы.
6. Не создавай чрезмерно короткие TTS-запросы.
7. Сохрани правильный порядок аудиофрагментов.
8. Исключи повторение и потерю слов.
9. Сохрани возможность моментальной остановки речи.
10. Не блокируй интерфейс во время нормализации.

Не переписывай сам Rust TTS и не изменяй оригинальный голос.

НАЧИНАЙ РЕАЛИЗАЦИЮ.

Смотри, у нас обнаружился ещё один косяк: английские технические сокращения и дефисы.
Например, Джарвис должен говорить «вай-фай» вместо Wi-Fi, «ви-пи-эн протоколы» вместо VPN-протоколы, а WPA3 — «дабл-ю пи эй три».
И важный момент: дефис не нужно произносить как слово «тире». В большинстве таких названий он просто соединяет части слова.
Я бы добавил это в тот же модуль нормализации речи, который мы уже поручили Codex. Пусть он перед отправкой текста в TTS распознаёт технические сокращения, разные виды дефисов и правильно преобразует их в русское произношение.
Но оригинальный текст на экране оставляем нетронутым, и голос Джарвиса не меняем.
Так мы исправим не только Wi-Fi и WPA, но и другие технические термины, которые он постоянно будет встречать
