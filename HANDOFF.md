# J.A.R.V.I.S. · состояние на 19 ноября 2026

## Запуск и выбор модели

Проект на Mac продолжен поверх существующего Rust/Tauri 2/Next.js. Итоговый пакет — `src-tauri/target/release/bundle/macos/Jarvis.app`. По последнему указанию владельца основной профиль — **Groq**, URL `https://api.groq.com/openai/v1`, модель `openai/gpt-oss-120b`. Сервер /models вернул 200 и включал этот ID. Потоковый проверочный запрос с get_time вернул 200 и tool_calls. Модель и провайдер видны в HUD. Ключ передаётся только разрешённому origin.

Ранее DeepSeek через OmniRouter один раз ответил «Париж.» по SSE. Повторные запросы получили HTTP 402 и 503. OmniRouter теперь дополнительный профиль. Старый ключ этого провайдера был в пользовательской копии ТЗ в audit/PROJECT J.md, включая Git-коммит fce6cdd в истории remote-tracking ветки. В рабочей копии значение отредактировано, владельцу сообщено о необходимости отзыва. История Git не переписывалась.

Принятый владельцем сервер Rust TTS на Xeon получает запросы через локальный SSH-проброс 127.0.0.1:18181 → 127.0.0.1:8181. Rust-клиент использует отдельный Bearer. Backend-конфигурация и русская модель STT хранятся в Application Support/com.jarvis.desktop. У файла backend.env права 0600.

## Реализовано

- `src-tauri/src/{core,events,provider,desktop}.rs` — координация диалога, типизированные события, SSE, ограниченный контекст, смена профиля и отмена.
- `storage.rs` — SQLite, диалоги, выбор настроек, подтверждённые предпочтения, удаление. `tools.rs` — семь диагностических операций и политика разрешений. Для изменяющих операций исполнителей нет.
- `tts.rs` — буфер законченных фраз, защищённый HTTP, раннее воспроизведение, bounded PCM, отмена и тайм-аут аудиоустройства.
- `audio.rs`, `capture.rs`, `native/audio.m` — нативное распознавание русской речи Zipformer, системный микрофон, VAD, push-to-talk и VoiceProcessingIO в постоянном режиме. При прерывании очищаются очереди предыдущей реплики. Для macOS голосовой выход микшируется в частоту ввода перед эхоподавлением.
- `src/components/hud.tsx`, `core-display.tsx`, `src/lib/console.ts`, `src/app/globals.css` — HUD, Canvas-ядро с реакцией на уровень звука, телеметрия, текстовый ввод, настройки и управление памятью.
- `scripts/install-stt.sh`, `scripts/stt.sha256`, `scripts/tts-tunnel.sh`, `.env.example`, `README.md` — воспроизводимая установка и запуск.

## Наблюдаемые результаты

| Сценарий | Измерено |
|---|---|
| Упакованное приложение на Mac M2 | Окно tauri://localhost, живые данные CPU/RAM, GPU Apple M2, видны Groq и активная модель. |
| Ручной ввод текста через HUD | На вопрос о времени приложение показало «Сейчас 00:08.» и передало первый PCM в AVAudioPlayerNode через 1256 мс после начала запроса. |
| Сквозной тест на сохранённой записи | Холодный локальный STT распознал «добрый вечер сэр» за 976 мс. После распознавания первый текст Groq пришёл за 583 мс, первый PCM был поставлен в очередь через 1037 мс. От начала STT до завершения воспроизведения прошло 3519 мс. |
| Повтор сквозного теста | STT 1299 мс, от начала запроса к Groq до первого текста 360 мс, до первого PCM 596 мс. Ответ отличался по длине. Полный цикл занял 5003 мс. |
| Отмена во время озвучивания | После первого PCM следующего ответа вызвана штатная остановка. Она завершилась за 1 мс, число занятых буферов вывода после остановки равно нулю. |
| Реальный встроенный микрофон | При подаче контрольной фразы через динамики ручной режим распознал «добрый вечер сэр это он говорил». Добавочные слова слышны в расшифровке. Groq ответил «Добрый вечер, сэр. Чем могу помочь?», HUD перешёл в SPEAKING, первый PCM через 786 мс после старта запроса. |
| Постоянное прослушивание | После согласования частот запуск VoiceProcessingIO прошёл, в HUD появился LISTENING. При выключении режим вернулся в IDLE и микрофон закрылся. |
| Память | Записанные сообщения остались в HUD после закрытия и повторного запуска приложения. Тест SQLite также проверяет раздельные сессии и удаление предпочтений. |
| Прокрутка диалога | В WebKit при окне 1320×850 и потоковом ответе на 100 строк поле команды ранее смещалось с 753 до 2455 px от верха страницы. После исправления оно осталось на 737 px. В окне 800×600 поле осталось на 487 px. При ручной прокрутке позиция истории сохранилась во время продолжения и сохранения ответа. В собранном Jarvis.app проверен отдельный диалог с ответом в 20 строк. |

Показатель первого PCM фиксируется, когда нативный плеер принимает первый блок. Акустическую задержку до уха отдельным измерительным микрофоном не измеряли.

## Проверки и следующий этап

```sh
npm run check
npm run desktop:build -- --bundles app
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo clippy --release --locked --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
cargo test --release --locked --manifest-path src-tauri/Cargo.toml
```

Два дополнительных теста с реальными моделями запускаются отдельно с переменными окружения из README и параметром `-- --ignored --nocapture`. Контрольное воспроизведение использует реальный выход Mac и действующий TTS.

Финальная сборка с типизированными IPC-событиями прошла npm run check, выпуск Jarvis.app, cargo fmt, Clippy и восемь обычных Rust-тестов. Оба приёмочных теста с реальными моделями также прошли. Финальный сквозной прогон: STT 1156 мс, первый текст 710 мс, первый блок воспроизведения 929 мс после старта AI-запроса, до окончания воспроизведения 3429 мс от начала STT. Отмена активного воспроизведения — 3 мс и ноль буферов в плеере.

Остаётся приёмка качества hands-free в реальной комнате: перебить ассистента голосом в середине фразы при разной громкости, проверить ложные срабатывания на его собственный голос и при необходимости настроить пороги VAD. Микрофон и рендеринг проверены на встроенных устройствах MacBook Pro. После перезагрузки проверочного Xeon или разрыва SSH требуется восстановить тестовый TTS и туннель по README. Для выпуска на другие Mac потребуется отдельная подпись и нотарификация.
