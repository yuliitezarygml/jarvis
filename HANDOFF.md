В исходной версии реестр публиковал семь диагностических функций. Для шести имён изменяющих действий он возвращал отказ. Сборка Tauri 2 на установленном Rust MSVC прошла на Windows. Выбран нативный `PlatformBackend`. Ветка macOS использует прежнюю телеметрию и AVFoundation. На Windows добавлены захват WinMM с кадрами по 16 мс и воспроизведение PCM16 24 кГц. ### Что осталось до полной приёмки

- Серверная очередь отложена по указанию «пока локально». Сервис jarvis-kb, расписание, Ed25519, HTTPS Range, автоматическая синхронизация и резервный сетевой поиск ещё предстоят. При автономной установке Jarvis раз в пять секунд проверяет изменение локальных файлов. Во время проверки новой версии поиск обслуживает предыдущая проверенная копия. Временную копию SQLite с ограниченным кешем страниц процесс освобождает при смене версии или выходе. На Xeon в этой работе ничего не развёртывалось.
- Не подключены общесистемные изменения реестра, служб, задач, ПО, драйверов, брандмауэра, hosts, пользователей и загрузки, произвольные пользовательские каталоги, архивы, управление питанием и ввод в сторонние окна. Поддержка домена в таблице выше обозначает только перечисленные операции.
- Для Windows 10 и 11 требуются отдельные VM-прогоны микрофона, динамиков, остановки, корзины, восстановления файлов, UAC, отключения брокера и его тайм-аута. Проверку диагностики в каждой VM запускает `cargo test --release --locked --manifest-path src-tauri/Cargo.toml windows_vm_diagnostics -- --ignored` с `JARVIS_TEST_VM_FAMILY`, равным `Windows 10` или `Windows 11`. Статус vm_verified выставляется только после фактической проверки конкретной записи.
- Новая сборка macOS не проверялась на этом Windows-хосте. Сквозной голосовой вызов Windows → TTS требует отдельного токена сервиса и проверки на VM. Результаты старой macOS-сборки сохранены ниже.

## Запуск и выбор модели

Проект на Mac продолжен поверх существующего Rust/Tauri 2/Next.js. Итоговый пакет — `src-tauri/target/release/bundle/macos/Jarvis.app`. По последнему указанию владельца основной профиль — **Groq**, URL `https://api.groq.com/openai/v1`, модель `openai/gpt-oss-120b`. Сервер /models вернул 200 и включал этот ID. Потоковый проверочный запрос с get_time вернул 200 и tool_calls. Провайдер и модель доступны в настройках. В левой панели HUD ядро подписано «JARVIS AI v2 — Цезарь». Ключ передаётся только разрешённому origin.

Ранее DeepSeek через OmniRouter один раз ответил «Париж.» по SSE. Повторные запросы получили HTTP 402 и 503. OmniRouter теперь дополнительный профиль. Старый ключ этого провайдера был в пользовательской копии ТЗ в audit/PROJECT J.md, включая Git-коммит fce6cdd в истории remote-tracking ветки. В рабочей копии значение отредактировано, владельцу сообщено о необходимости отзыва. История Git не переписывалась.

Принятый владельцем сервер Rust TTS на Xeon получает запросы через прямое HTTPS-соединение с 192.168.50.38:8443. Rust-клиент использует отдельный Bearer. Backend-конфигурация и русская модель STT хранятся в Application Support/com.jarvis.desktop. У файла backend.env права 0600.

## Реализовано

- `src-tauri/src/{core,events,provider,desktop}.rs` — координация диалога, типизированные события, SSE, ограниченный контекст, смена профиля и отмена.
- `storage.rs` — SQLite, диалоги, выбор настроек, подтверждённые предпочтения, удаление. `tools.rs` — семь диагностических операций и политика разрешений. Для изменяющих операций исполнителей нет.
- `tts.rs` — буфер законченных фраз, защищённый HTTP, раннее воспроизведение, bounded PCM, отмена и тайм-аут аудиоустройства.
- `audio.rs`, `capture.rs`, `native/audio.m` — нативное распознавание русской речи Zipformer, системный микрофон, VAD, push-to-talk и VoiceProcessingIO в постоянном режиме. При прерывании очищаются очереди предыдущей реплики. Для macOS голосовой выход микшируется в частоту ввода перед эхоподавлением.
- `src/components/hud.tsx`, `core-display.tsx`, `src/lib/console.ts`, `src/app/globals.css` — HUD, Canvas-ядро с реакцией на уровень звука, телеметрия, текстовый ввод, настройки и управление памятью.
- `scripts/install-stt.sh`, `scripts/stt.sha256`, `.env.example`, `README.md` — воспроизводимая установка и запуск.

## Живая русская речь · 19 ноября 2026

В установленном Zipformer используется `OfflineRecognizer`, который получает всю запись после окончания ввода. Для промежуточных результатов добавлена русская потоковая T-one CTC. Нативный аудиовход по-прежнему отдаёт mono PCM 16 кГц. Sherpa преобразует его в 8 кГц для T-one, а исходные 16 кГц сохраняются в памяти для уточняющего прохода Zipformer. На каждой фразе создаётся новый поток. [Описание и параметры T-one](https://k2-fsa.github.io/sherpa/onnx/pretrained_models/online-ctc/t-one-ctc-models.html)

`scripts/install-stt.sh` устанавливает обе модели и проверяет SHA-256. Для существующей установки загружаются недостающие файлы. T-one находится в `stt/streaming`. При отсутствующем или повреждённом файле потоковой модели пульт сообщает, что текст появится в конце фразы. В этом случае работает Zipformer. Если уточнение через Zipformer недоступно, используется финал потока T-one.

Событие Tauri `speech` передаёт в React состояние микрофонной расшифровки. Черновик остаётся в интерфейсе, а `Core::start` получает один финальный текст. Голубая волна строится по последним измерениям RMS с микрофона. «Завершить» отправляет запись на распознавание. «Остановить» отменяет запись, генерацию и воспроизведение.

## Автоматический конец фразы и прямой HTTPS API

Earshot обрабатывает 16-миллисекундные кадры. Пауза завершает реплику только после зарегистрированной речи. В настройках доступны 800–1200 мс, по умолчанию 1000 мс. Ручное завершение и отдельная остановка ответа доступны. Активация по обращению «Джарвис» включается явно.

В тесте с записанным PCM при порогах 800 и 1200 мс конец фиксировался через 727 и 1206 мс относительно последнего ненулевого отсчёта обрезанной записи. Внутренняя пауза 450 мс сохранила единую команду, финал пришёл через 940 мс при настройке 1000 мс. Ровный шум, гул и отменённая запись дали ноль отправок. Через динамик и встроенный микрофон Mac без ручного завершения прошли два обращения подряд. На вопрос о столице Франции Groq вернул «Париж.» (первый PCM через 408 мс), на вопрос о сумме семи и пяти — «12» (823 мс). При более тихом воспроизведении один пробный сигнал не активировал детектор.

На момент перевода в эксплуатацию `jarvis-tts-rs.service` был active/enabled и слушал 8443. Python-служба `jarvis-tts.service` была inactive/disabled, PID 0, preview остановлен. Порты 8080 и 8181 закрыты. Клиентский запрос готовности вернул 401 без токена и 200 с токеном, голос `jarvis-ru`, 24 кГц. Поток синтеза вернул 103680 байт PCM. Диалог на Mac прошёл после закрытия административного SSH-соединения. Корневой сертификат Xeon используется только клиентом TTS для настроенного origin.

## Озвучивание формул, таблиц и технических названий

Поток Groq расходится на две ветви в `core.rs`. Исходные дельты идут в HUD, история SQLite получает их точную конкатенацию. Отдельная задача в `tts.rs` читает копию дельт в порядке поступления и через `speech_normalizer.rs` отправляет готовые фразы в `POST /tts/stream`. На один ответ действует общий лимит 40 000 байтов исходного текста. Прежнее переполнение очереди из 48 коротких фраз могло оборвать текст в интерфейсе. Теперь скорость аудиовыхода не прерывает получение текста. Один запрос синтеза содержит до 260 символов. Воспроизведение остаётся последовательным, на выходе максимум пять буферов PCM.

Для чисел используются русские склонения и порядковые числительные. Десятичная часть читается по записанным цифрам. CommonMark разбирает заголовки, списки, код, ссылки и таблицы. Строка таблицы озвучивается с названиями столбцов. Код и явные адреса читаются с названиями технических символов, именованная ссылка — по подписи. В словаре терминов есть Wi-Fi, VPN, WPA3 и другие сокращения. Неоднозначные обозначения в явном коде и неподдерживаемые конструкции LaTeX читаются буквально. Для отдельных чисел в связном русском тексте сохраняется штатный контекстный нормализатор голоса.

Упакованное arm64-приложение запущено на этом Mac. В отдельном диалоге HUD показал исходную строку «3³ = 27. √16 = 4. Wi-Fi и WPA3.», перешёл из PROCESSING в SPEAKING и зафиксировал первый звук через 596 мс. В настройках выбран Groq `openai/gpt-oss-120b`, озвучивание включено.

Финальный последовательный прогон всех восьми приёмочных тестов прошёл. В тесте раннего старта источник удерживал последнюю часть ответа до события SPEAKING. Первая уже законченная формула поступила на реальный аудиовыход через 194 мс при открытом канале текста. Затем приложение доиграло вторую формулу, регистрация начала воспроизведения содержала обе фразы ровно по одному разу, очередь опустела. В финальном аудиосравнении Zipformer точно расшифровал обе математические фразы и «вай фай», но в текстовой расшифровке WPA3 пропустил заключительное «три». В переданном TTS тексте это слово присутствует. Сохранённая пара WAV соответствует второму прогону.
