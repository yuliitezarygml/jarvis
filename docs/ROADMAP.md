# План на будущее: что бесит тестеров — исправить после системы обновлений


## Context
Люди протестировали Джарвиса и сказали, что их бесит:
1. **Долго думает** перед ответом и действием.
2. **Тяжело управляет компьютером**: на простое «открой блокнот, напиши привет» что-то ищет, пробует, ошибается — вместо «открыл → написал → всё». «Открой новую вкладку YouTube и включи первое видео» — включает случайное видео, а не первое, не ждёт загрузки.
3. **Не всегда правильно понимает команды**, особенно длинные из нескольких действий («сделай то, потом это, потом…») — распознанный текст без запятых, модель путается.
4. **Ошибки наружу**: «голосовая модель вернула ошибку» и подобное — пользователь видит/слышит сбои.
(Нагрузку на систему по решению владельца не трогаем.)

Цель: обычные команды — **быстро, с первого раза, без ошибок и без лишних шагов**.

## 0. Сначала измерить (неделя 1)
- Замер каждого этапа команды в журнале и в HUD «Журнал»: распознавание → первая мысль модели → каждый инструмент → первый звук ответа. Сейчас видно только общее время.
- **Набор из 50 реальных команд** тестеров (с ожидаемыми действиями): «открой блокнот и напиши привет», «включи первое видео на YouTube», «закрой хром», «сделай громче», составные команды… — прогон после каждой правки: % выполненных с первого раза, время, число шагов. Это главный показатель «бесит / не бесит».
- Кнопка «Отправить отчёт» (журнал + последние команды, без ключей и личного) — тестеры присылают случаи, когда что-то не так.

## 1. «Долго думает» → быстрые команды без раздумий
- **Быстрый путь без языковой модели** для частых команд: «открой/закрой X», «громче/тише», «сверни/разверни», «напиши в блокноте …», «включи/пауза» — распознаются локально по шаблонам и сразу выполняются готовым сценарием (миллисекунды вместо секунд). Модель — только когда команда не узнана.
- **Простое — быстрой моделью**, сложное — умной: короткие команды в модель роли `fast` (gpt-oss-20b), длинные/многошаговые — в `brain`; у reasoning-моделей низкий уровень рассуждений для простых шагов.
- **Сразу голосом**: «Открываю…» звучит в момент начала действия, а не после всего.
- Меньше лишних обращений к модели: инструменты нужной группы сразу (без `tools_load`), меньше текста в запросе, память подгружается только когда относится к делу.
- Лимиты Groq (429): заранее распределять запросы по двум ключам и OpenRouter, а не ждать ошибку.

## 2. «Тяжело управляет ПК» → готовые надёжные сценарии
- **Навыки** — проверенные пошаговые сценарии с ожиданием и проверкой результата, без «поиска наугад»:
  - «открой программу + напиши текст»: открыть → дождаться окна → фокус → ввести → проверить, что текст в окне;
  - браузер: «новая вкладка», «открой сайт», «найди на YouTube …», «включи **первое** видео» — дождаться загрузки страницы, взять первый результат по порядку на странице (через дерево элементов окна / адрес поиска YouTube), открыть его и проверить, что видео играет;
  - окна: свернуть/развернуть/закрыть/переключиться; громкость, медиа-клавиши.
- Модель выбирает навык и параметры («YouTube», «первое»), а не управляет мышью по шагам; свободное управление мышью/скриншотами — только запасной путь.
- Ожидание вместо спешки: «дождаться окна/загрузки» с таймаутом вместо фиксированных пауз и повторных скриншотов.
- Каждый навык — с тестом в наборе из 50 команд.

## 3. Правильно понимать команды
- **Разбор составной команды** до выполнения: «открой блокнот напиши привет и сохрани на рабочий стол» → список шагов; длинную команду Джарвис кратко повторяет («Открываю блокнот, пишу «привет», сохраняю») и делает по шагам, отчитываясь.
- Восстановление запятых и границ фраз в распознанном тексте; английские названия — уже делается (`docs/STT.md`).
- Уточняющий вопрос только когда правда непонятно, а не на каждую команду.
- **Знаки препинания и интонация в распознанном тексте**: вопрос — со знаком «?» («Привет, как дела?»), восклицание — «!», запятые и точки там, где они слышны. Как:
  - по словам: вопросительные слова и частицы («как», «что», «где», «почему», «ли», «а ты…»);
  - по голосу: **интонация** — подъём высоты голоса в конце фразы (вопрос), громкость/резкость (восклицание); высоту тона считать из звука фразы (у нас уже есть замеры голоса в VAD);
  - облачный Whisper сам ставит знаки — брать их; для локального GigaAM — отдельная маленькая модель расстановки знаков (локально) + интонация;
  - модель Джарвиса получает текст с правильными знаками и понимает, что это вопрос, а не команда; тон речи (вопрос / просьба / раздражение) помогает отвечать в тон.
- Ошибки распознавания в командах («блокнод», «вэс код») — словарь программ из системы + память.

## 4. Никаких «модель вернула ошибку»
- Голос: если сервер голоса недоступен (адрес туннеля сменился, нет интернета) — **запасной локальный голос** (встроенный голос Windows или локальная модель), Джарвис продолжает говорить, а не молчит/ругается ошибкой. Постоянный адрес голоса вместо меняющегося trycloudflare (свой домен на Cloudflare) — чтобы у друзей не ломалось.
- Языковая модель: повтор и переход на запасную без вывода технических ошибок пользователю; по-человечески: «Секунду, связь медленная…».
- Все сбои — в журнал и «Отправить отчёт», а пользователю — короткая понятная фраза.

## 5. Красивый установщик в стиле Джарвиса (часть системы обновлений)
Вместо обычного серого установщика Windows — **свой установщик**: маленький `JARVIS-Setup.exe` (~5–10 МБ), сам скачивает программу с GitHub и ставит её. Оформление как у Джарвиса: тёмный фон, цвета темы, реактор, анимации.
Шаги:
1. **Приветствие + выбор папки** — «Куда установить Джарвиса?» (по умолчанию `%LOCALAPPDATA%\Programs\JARVIS`, кнопка «Изменить»), сколько места нужно, канал (Стабильная / Бета — по желанию, можно скрыть).
2. **Установка с визуализацией** — реактор крутится, полоса и подписи: «Скачиваю ядро… 42 МБ», «Скачиваю распознавание речи… 215 МБ», «Проверяю подпись», «Распаковываю», «Создаю ярлыки». Проверка подписи и sha256 (как в `docs/UPDATES.md`), при обрыве — продолжение, а не заново.
3. **Запуск** — «Готово» → кнопка «Запустить Джарвиса» (и галочки: ярлык на рабочем столе, запуск с Windows).
- Удаление — через «Приложения» Windows (запись в реестре), данные пользователя (`%APPDATA%\JARVIS`) — по галочке «удалить и настройки».
- Этот же установщик в режиме «обновление» (маленькое окно с прогрессом) используется встроенным обновлением программы — один механизм вместо двух. В `docs/UPDATES.md` этап 2 (NSIS) заменяется на этот установщик.
- Сделан на том же стеке (Rust + Tauri + наш фронтенд, общие стили и компонент реактора), отдельный крейт `installer/`.

## 6. Знакомство при первом запуске (онбординг)
После установки, при первом запуске:
1. **Окно приветствия** — HUD с реактором, Джарвис **говорит голосом**: «Здравствуйте. Меня зовут Джарвис — я ваш голосовой помощник для Windows. Я умею открывать программы, искать в интернете, управлять окнами, отвечать на вопросы…» (тексты — придумаем вместе; субтитры на экране).
2. **Экскурсия по программе** — затемнение экрана и **подсветка части интерфейса** с подписью, Джарвис объясняет каждую:
   - «Вот здесь я показываю, что слышу и что делаю» (субтитры, лента действий);
   - «Сюда можно написать команду текстом» (строка команд);
   - «Здесь настройки: голос, микрофон, модели, внешний вид»;
   - «Это я в уголке экрана — нажмите, чтобы развернуть» (виджет), трей, горячие клавиши Ctrl+Alt+J / Ctrl+Alt+K;
   - кнопки «Дальше» / «Назад» / «Пропустить», голос можно перебить.
3. **«Для начала работы нам нужно…»** — шаги настройки (проверка микрофона, ключ модели или приглашение `jarvis-invite.json`, как к вам обращаться, …) — **список шагов допишем вместе** (ты дополнишь).
- Пройденное знакомство запоминается (`config.json` → `onboarding_done`), повторить — Настройки → «Показать знакомство снова».

## Порядок и как поймём, что готово
0. Система обновлений (`docs/UPDATES.md`) вместе с установщиком (п. 5) и знакомством (п. 6).
1. Замеры и набор 50 команд → 2. Навыки (блокнот, браузер/YouTube, окна) → 3. Быстрый путь без модели → 4. Разбор составных команд → 5. Запасной голос и тихие ошибки.
**Готово**, когда на наборе из 50 команд: ≥ 90 % выполнены с первого раза; простые команды (открыть/написать/включить) — от конца фразы до начала действия ≤ 1,5 с; ни одной технической ошибки голосом/текстом пользователю за прогон.
