# Испытания Rust TTS на Xeon · 18 ноября 2026

Сервер выполнил синтез на CPU без обращения к прежней службе. Приёмка на слух остаётся открытой. Исходные веса акустической модели, токенизатор и запись голоса проверены по SHA-256. Финальная контрольная серия выполнена локальным HTTP-клиентом на том же Linux-сервере, с четырьмя вычислительными потоками. [Аудит модели](legacy.md) · [Проверка файлов](asset-check.txt) · [Динамические зависимости](linux-runtime.txt).

## Задержка и использование ресурсов

| Показатель | Измерение |
|---|---|
| Загрузка языковых моделей, акустической модели и голосового контекста | 4,389 с от начала загрузки до готовности модели |
| Первый PCM короткой фразы | 236 мс для первого запроса после старта, 79–82 мс для двух прогретых |
| Первый PCM длинного текста | 122–129 мс для двух прогретых |
| Генерация шести завершённых WAV | 370–1850 мс суммарного времени запроса на один файл, RTF 0,238–0,310 |
| Загрузка CPU | 393–463% во время одиночных WAV-запросов. 100% соответствует одному полностью занятому логическому CPU |
| Пиковая память | 1,834 GiB по MemoryPeak cgroup, 1,839 GiB по VmHWM процесса |
| Два одновременных запроса | Результаты через 339 и 699 мс с начала соответствующих запросов. Среднее ожидание очереди 168,8 мс |
| Двунаправленная передача | Первые 3840 байт PCM приняты при открытом потоке входного текста, затем клиент передал следующую фразу |

RTF — время от отправки запроса до получения последнего байта, делённое на длительность звука. Измерения первого звука относятся к получению первого непустого HTTP-фрагмента. Сеть до пользовательского устройства, буфер аудиодрайвера и физический динамик в эти задержки не входят. CPU вычислен по приращению utime+stime из /proc. Для двух одновременных запросов задержка очереди получена из приращения серверного счётчика. [Полная серия](checked-4.json) · [Статистика cgroup](checked-cgroup-4.txt).

## Один и тот же текст в двух движках

Измерены полные ответы с WAV. Обе серии запущены клиентом на Xeon, старый сервер получил шесть промахов в кэше. Запросы выполнялись последовательно. Акустический генератор использует шум, поэтому длительность речи может различаться между запусками. [Корпус](corpus.json) · [Старый сервер](legacy-server.json).

| Короткая фраза | 980 | 370 | 1,36 / 1,44 | 0,721 / 0,257 |
| Длинный текст | 3086 | 1850 | 5,52 / 7,76 | 0,559 / 0,238 |
| Английская фраза | 913 | 409 | 1,44 / 1,52 | 0,634 / 0,269 |
| Смешанный текст и CPU | 1416 | 614 | 2,40 / 2,32 | 0,590 / 0,265 |

| Пунктуация | 1469 | 660 | 2,32 / 2,32 | 0,633 / 0,285 |

В исходном HTTP API первые байты доступны после подготовки файла. Для короткой фразы время до заголовков составило 976 мс. Отдельная начальная серия через LAN дала WAV-эталоны, сохранённые для сравнения голоса. [Начальная серия с Mac](baseline.json).

Четыре потока выбраны для коротких реплик и совместной работы с другими службами. Восемь потоков дали лучший одиночный результат на длинном тексте при большем расходе CPU. С явной привязкой финальной сборки к логическим CPU 0–3 короткие фразы начали отдаваться через 74 и 80 мс, длинные — через 129 и 130 мс. ## Голос, произношение и паузы

Текст после нормализации и ударений совпал посимвольно для семи проверенных фраз, включая омографы. Сохранились и особенности эталона, например чтение времени «четырнадцать нуля тридцать». Поведение на произвольном тексте может отличаться, особенно при сложном делении предложений и аббревиатурах. [Парные текстовые эталоны](legacy-text.jsonl).

Для сравнения диктора WAV приведены к 16 кГц и обработаны WeSpeaker ResNet34, обученной на VoxCeleb. Среднее косинусное сходство между старыми и новыми записями составило **0,900**. Относительно исходного голосового референса среднее составило 0,751 для старой системы и 0,736 для Rust. Для оценки пауз посчитаны внутренние интервалы энергии ниже −40 dBFS длительностью от 120 мс по окнам 10 мс. ### Контроль разборчивости независимым распознавателем

Сохранённые WAV дополнительно расшифрованы русским Zipformer INT8 в режиме greedy search. Расшифровки приводятся как вывод распознавателя. Они помогают выбрать места для прослушивания, в особенности смешанную фразу и повтор «вы» в образце с пунктуацией.

| Фраза | Расшифровка исходного WAV | Расшифровка Rust WAV |
|---|---|---|
| Короткая фраза | добрый вечер сэр | добрый вечер сэр |
| Длинный текст | диагностика завершена вся системы работают в штатном режиме связь с сервером устойчива готов принять следующую команду | диагностика завершена все системы работают в штатном режиме связь с сервером устойчиво готов принять следующую команду |
| Английская фраза | гуд морнинг сэр | гуд морнинг сэр |
| Смешанный текст и CPU | джарвис проверь виндовсы сипи | джарвис проверь виндовсем |
| Число и время | температура двадцать пять градусов время четырнадцать нуля тридцать | температура двадцать пять градусов время четырнадцать нуля тридцать |
| Пунктуация | сэр вы здесь отлично | сэр вы вы здесь отлично |

Чтобы воспроизвести расшифровку, укажите каталог распакованного sherpa-onnx-zipformer-ru-int8-2025-04-20 в JARVIS_EVAL_ASR при запуске инструмента оценки. [Модели ASR sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx/releases/tag/asr-models).

Оценка диктора отражает близость голосовых признаков. Интонация, естественность пауз, произношение и приемлемость сходства для владельца требуют прослушивания этих пар. В тестах не выставлялась оценка слушателя. Английская и смешанная фразы обрабатываются тем же русским голосом и транслитерацией, что и в прежнем API.

## Функциональные проверки

- На Mac прошли cargo fmt --check, cargo check --workspace, cargo clippy --workspace -- -D warnings, cargo test --workspace (22 теста) и cargo build --release --locked. На Linux собран release для Haswell (rustc 1.100.0), проверен реальный HTTP-синтез. Шаблон постоянной службы прошёл systemd-analyze verify.
- Шесть пар WAV содержат моно PCM16 24 кГц. Проверены поля RIFF, размер данных, длительность и ненулевая энергия для Rust-ответов. MP3 при speed=1.25 декодируется как mono 24 кГц.
- Проверены пустой ввод, пробелы, символы без букв или цифр, превышение лимита и неподдерживаемые значения языка, голоса, формата и скорости. Отмена активной генерации возвращает 202, следующий запрос выдаёт звук. Пять занятых мест и шестой запрос дают 429, после отмены всех работ новый запрос получает WAV.
- Пустой, слишком длинный и некорректный UTF-8 в text/plain до начала аудио дали 422 invalid_input. При освобождении модели ожидающий запрос потока начал возвращать данные раньше ранее поставленного в очередь WAV.
- Защищённый preview на 127.0.0.1:8181 вернул 401 без токена и 200 с токеном. Входной поток и выходной PCM проверены одним HTTP-соединением. Клиент получил звук до завершения отправки текста.

Повторный запуск проверок и подключение к preview описаны в [README](../README.md). Скрипт тестового клиента сохраняет новые аудиозаписи и результаты. Для независимых повторов используйте отдельную копию каталога примеров. Для офлайн-оценки голоса нужны FFmpeg, Node, sherpa-onnx-node 2.0.1 и файл wespeaker_en_voxceleb_resnet34.onnx, указанный через JARVIS_WESPEAKER. Его SHA-256 записан в JSON. Запустите node tools/voice-compare.cjs из корня компонента.

## Состояние старой службы

Во время испытаний, 18 ноября в 23:20:16 по Кишинёву (21:20:16 UTC), systemd зарегистрировал SIGKILL прежнего процесса jarvis-tts.service. Политика Restart=on-failure запустила процесс в 23:20:21, завершение старта приложения зафиксировано в 23:20:44. Команды остановки или перезапуска этой службы в ходе работ не выполнялись. Счётчик oom_kill доступного cgroup показывал 0. Причина сигнала не установлена. После события старый API вернул ok=true и отработал повторную серию запросов с WAV. Переключение клиентов на Rust не выполнялось. [Журнал перезапуска](legacy-restart.txt) · [Состояние службы](linux-runtime.txt).
